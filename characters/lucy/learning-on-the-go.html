1C# if you know Python and C++

Short version: C# looks like C++, but behaves more like Python. You get types and braces, and memory looks after itself.

It's compiled, like C++

Nothing runs until the whole program compiles.

Python reads your file line by line and only complains when it gets to a bad line. C# checks every file first, then builds one .exe. A single typo anywhere stops the whole build.

The compiler here is csc.exe, and it comes with Windows. There are no header files, unlike C++. Every file can see every other file it's compiled with.

Memory cleans itself up, like Python

No delete, no pointers to worry about.

You make things with new, like in C++, but you never free them. A garbage collector does that, as in Python. So you can't get the classic C++ crash from using memory that's already been freed.

Every variable has a type

Like C++. A string stays a string.

py
name = "Talia"
c++
std::string name = "Talia";
c#
string name = "Talia";

You can write var name = "Talia"; and C# works out the type, a bit like auto in C++. It's still fixed as a string afterwards.

Lists and arrays

string[] has a fixed size. List<string> can grow.

py
lines = ["Hi", "Yo"]
c++
std::vector<std::string>
c#
List<string> or string[]

The <string> part works like C++ templates: it says what's inside.

null is Python's None

A missing value. Using it by accident crashes.

Calling something on null throws a NullReferenceException, the C# version of Python's 'NoneType' object has no attribute.

You'll see ?? a lot. a ?? b means "use a, or b if a is null".

py
x if x is not None else ""
c#
x ?? ""

Everything lives inside a class

C# has no loose functions. A static class is how it does a Python module.

Python lets you write def at the top of a file. C# doesn't. So when the code only needs a bag of functions and values, it uses a static class: you can't make objects from it, you just call Character.Declined, the way you'd call character.declined after an import.

internal means "anyone in this program can use it, nobody outside". private means "only this class".

Namespaces, like C++

A family name for a group of classes.

All of Capri's code sits in namespace CapriDesktop { ... }. using System; at the top of a file is like using namespace std; in C++, or a Python import that lets you skip the prefix.

This project is stuck on C# 5

Many tutorials show newer C#. Some of it won't compile here.

The compiler that comes with Windows only knows C# 5, from 2012. If you copy something from the internet and it fails, check for these first:

  • $"Hi {name}" (like a Python f-string): write "Hi " + name instead
  • thing?.Name: check for null first instead
  • int Twice(int x) => x * 2;: use a normal { return x * 2; }
  • (a, b) tuples like Python's: not available

Reading a compiler error

Go straight to the line and column it names.

Talk.cs(120,34): error CS1009:
  Unrecognized escape sequence

That's file Talk.cs, line 120, character 34. The real mistake is usually right there or just before it. On your PC the message comes in German (Fehler means error), but the line and column are the same.

If the path has character-talia in it, that's the build's copy. Fix it in app\, not in the copy.

2C# you've already met here

Real lines from this repo, explained.

const versus static readonly

Both mean "never changes". They differ in when the value is set.

internal const string Declined = "Nah. Not that one, Choomie.";
internal static readonly string[] PopLines = { "Bored.", ... };

const is baked in at build time, like constexpr in C++. It only works for simple things: text and numbers. A list isn't simple, so PopLines is static readonly: it's set once when the app starts, and can't be changed after.

Lachy's Brain.Declined is a const, so Talia's has to be one too.

@"..." is Python's r"..."

A raw string: backslashes stay as backslashes.

py
r"\d+\s"
c#
@"\d+\s"

Regex patterns are full of \, so they use @. Forgetting it gives "unrecognized escape sequence". One odd difference: inside @"...", a quote mark is written twice, "".

A variable that holds a function

Func<A, B, R> is a function you can store and swap. The last type is what it returns.

static Func<string, string, string> Call = Ask;

Read it as: Call takes two strings and gives back a string, and right now it is Ask. It's like keeping a function in a Python variable, or a std::function in C++.

The self-test swaps Call for a fake, so it can test without the real YouTube Music app. More in chapter 5.

app/YouTubeMusic.cs · log of 31 Oct

Two things called Character

When names clash, the closest one wins. Write the full name to pick the other.

Inside Lachy's Brain class, Character already means her whole prompt, a string. So Character.Declined there failed with "a string has no Declined".

The fix is the full name: CapriDesktop.Character.Declined. It's like two people called Alex in one room: you add the family name. Python has the same thing when a local variable hides an imported module.

app/Brain.cs · log of 31 Oct

The build has a guest list

A new .cs file does nothing until it's named in $sources.

Python finds files when you import them. Here the build script hands csc.exe an exact list of files, in ci/build-windows.ps1. That's why our 'Character', 'YouTubeMusic' are written into that list, and why it's where merges keep conflicting.

3How the fork stays mergeable

Lachy keeps updating Capri. Every idea here is about taking his updates without a fight.

Our code goes in our own files

His files get one-line hooks that say "ask our file".

If our code sits inside his file, one day his change lands next to ours and Git stops to ask. If all we added is one line, that conflict is easy to fix. It's less tidy (Spotify in one file, YouTube Music in another), but it keeps merges cheap.

log of 31 Oct

Point, don't move

Leave his list where it is and make it point at ours.

private static readonly string[] PopLines = Character.PopLines;

That one line in app/Capri.cs is the only difference from his file. Every place that used his list now gets ours, and none of them changed.

log of 31 Oct

Change a copy, not the original

Her name is swapped in a throwaway copy of the code at build time.

Use-Character.ps1 copies the code, replaces the phrases from her names.txt in the copy, and compiles that. Lachy's files never change, so his updates can't conflict over her name.

The catch: a find-and-replace only finds what it's told to. New text from Lachy that says "Capri" shows up as Capri until someone adds a rule for it.

What's shared, and what's hers

Things that belong to you are shared. Things that belong to her are kept apart.

Settings, keys and voices are yours, so all characters share them. Memories, chats and personality are hers, so each character has her own folder. Otherwise Talia would read Lucy's memories as her own.

log of 4 Nov

An app's identity is more than its name

Windows tells apps apart by things you never see.

The settings folder, the autostart entry, and a mutex: a lock that makes sure only one copy runs. If two apps share these, they fight. That's why the build renames them as well as the words on screen.

log of 1 Nov

Mods only open the doors their author chose

Ask "is what I want behind one of its doors?", not "how powerful is it?"

Lachy's mods can change her looks, names and sounds. Who she is stays in his code. That's why Talia still needs her own build.

4Git, in small bites

A conflict means two changes touched

Git compares lines. Two edits on the same line, or next to each other, make it stop.

It doesn't understand what either edit means. That's also why a conflict isn't always a disagreement: Lachy changed a colour and we changed a name on the same line, so the answer was to keep both.

log of 4 Nov · 5 Nov

A clean merge can still be wrong

No conflict only means no two edits touched.

His change can break ours one file away and Git won't notice. So after a merge, compiling and testing still matter.

log of 2 Nov

A branch is just a name on a commit

Moving a branch copies nothing.

When main took in talia-built-in, Git only moved the name main forward to a newer commit. All the history stayed as it was.

log of 5 Nov

A worktree is a second folder for one repo

Its own files, but the same history.

The merge script runs in one, so it doesn't disturb whatever another session is doing in your main folder.

5Tests, and failures that hide

Tests swap out the real world

Put a fake function in the variable, run the check, put the real one back.

Func<string, string, string> callWas = Call;
Call = fake;   // writes down what was sent
// ... run the checks ...
Call = callWas;

This tests Talia's side without the YouTube Music app, the internet or a real song. Python people know this as mocking.

log of 4 Nov

A fingerprint of a text

SHA-256 turns any text into a short code. Change one letter and the code changes completely.

The self-test keeps the code for her personality, so any change is noticed. The same idea checks downloaded installers: the updater only runs one whose code matches SHA256SUMS.txt. It's what Python's hashlib.sha256 does.

log of 1 Nov

GET asks, POST does

An API is a door an app leaves open for other programs.

YouTube Music runs a small web server at 127.0.0.1 ("this PC", nothing goes online). GET /track/state asks if a song is liked. POST /track/like likes it. Same idea as requests.get and requests.post in Python.
